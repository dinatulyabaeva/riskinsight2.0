# Yandex AI Studio: подключение RiskInsight 2.2

В версии 2.2 добавлен адаптер Responses API. Языковая модель выбирает аналитические инструменты; RiskInsight валидирует параметры и выполняет настоящий MCP в отдельном процессе. Числа, текст отчёта, таблицы и графики строятся из текущих результатов MCP. Смена провайдера не меняет формулы, источник данных и правила проверки.

Поддержка API проверяется тестами с заданными HTTP-ответами. Успешное подключение конкретного ключа и качество конкретной модели подтверждает только отдельный живой прогон. Платный API включается явными настройками владельца; автоматической смены модели или платного резервного провайдера нет.

## 1. Настройки Render

Откройте сервис **riskinsight → Environment → Edit**. Введите значения в отдельные поля:

| Имя | Значение |
|---|---|
| `APP_MODE` | `llm` |
| `LLM_API_STYLE` | `responses` |
| `LLM_BASE_URL` | `https://ai.api.cloud.yandex.net/v1` |
| `LLM_MODEL` | `gpt://ВАШ_FOLDER_ID/aliceai-llm-flash` |
| `LLM_AUTH_SCHEME` | `api-key` |
| `LLM_PROJECT` | Ваш ID каталога (Folder ID) |
| `LLM_API_KEY` | Секретная часть созданного API-ключа Яндекса |
| `LLM_TIMEOUT_SECONDS` | `180` |
| `MAX_OUTPUT_TOKENS` | `2048` |
| `MAX_AGENT_ROUNDS` | `3` |

Замените `ВАШ_FOLDER_ID` внутри `LLM_MODEL` на тот же идентификатор, что в `LLM_PROJECT`. Не оставляйте угловые скобки или кавычки. Используйте секрет ключа, а не его имя/ID. Существующий `APP_ACCESS_TOKEN` — отдельный токен входа в приложение.

Сохраните настройки с повторным развёртыванием. Для `runtime: docker` используется команда из Dockerfile; отдельный скрипт проверки ключа в команде запуска не нужен. Если ранее был установлен временный **Docker Command** для диагностики провайдера, удалите именно этот override, чтобы запускалась обычная команда приложения.

Проверьте `https://riskinsight.onrender.com/api/health`: ожидаются `version: "2.2.0"`, `features.responses_api: true`, `mode: "llm"`, `llm_configured: true`. Это проверка настроек и сборки, не запрос к модели. Полный `build_commit` должен совпадать с коммитом текущего deploy.

API-ключ и токен доступа не добавляются в GitHub, README, команды с открытым значением или переписку. Ключ модели нужен только серверу Render; локальный Ollama не участвует.

## 2. Права в Яндексе

Согласно официальной документации Responses API, сервисному аккаунту нужны роли `ai.assistants.editor` и `ai.languageModels.user` на используемый каталог. Для API-ключа нужен scope `yc.ai.foundationModels.execute`. Ключи, создаваемые через AI Studio по его инструкции, получают указанные разрешения.

Адаптер отправляет `Authorization: Api-Key …` и `OpenAI-Project: <Folder ID>`. Если `LLM_PROJECT` пуст, для Yandex endpoint каталог извлекается из `gpt://…`; явно заданное несовпадение отклоняется до обращения к API. Для другого Responses-совместимого сервиса можно явно выбрать `LLM_AUTH_SCHEME=bearer` и его модель/endpoint.

`store:false` отключает сохранение Responses-объекта для последующего получения через API. Это не заявление об отключении всех журналов провайдера. Рабочая память диалога остаётся в RiskInsight и действует по описанным в README ограничениям.

## 3. Первый короткий живой прогон

Сначала проверьте один вопрос на опубликованном сервисе и сохраните результат. Эта проверка использует синтетический тестовый XLSX из репозитория, настоящий MCP и независимый числовой эталон. Она отправляет **один вопрос**, допускающий до **трёх обращений к модели** при исправлении её плана. Запросы расходуют квоту/бюджет выбранного API.

Из обновлённой локальной папки проекта в PowerShell:

```powershell
git pull --ff-only
$expectedCommit = (git rev-parse HEAD).Trim()
$serviceToken = Read-Host "APP_ACCESS_TOKEN сервиса Render" -AsSecureString
$env:APP_ACCESS_TOKEN = [System.Net.NetworkCredential]::new("", $serviceToken).Password
try {
    .\.venv\Scripts\python.exe -u -m scripts.eval_acceptance `
        --provider live `
        --base-url https://riskinsight.onrender.com `
        --expected-commit $expectedCommit `
        --limit 1 `
        --repeat 1 `
        --max-llm-requests 3 `
        --output reports/yandex-first-check.json
} finally {
    Remove-Item Env:APP_ACCESS_TOKEN -ErrorAction SilentlyContinue
    Remove-Variable serviceToken -ErrorAction SilentlyContinue
}
```

Введите токен **приложения Render** по приглашению, не API-ключ Яндекса. Ключ LLM остаётся на Render. Если сервер ещё обновляется и коммиты различаются, скрипт остановится до обращения к модели; дождитесь завершения deploy.

Успех первого прогона: `passed_all_criteria: 1`, `failed: 0`; в отчёте фактическая модель `gpt://…/aliceai-llm-flash`, `provenance.llm_called: true`, успешный `get_portfolio_summary`, проверенные числа и существующие MCP-ссылки. HTTP 200 от health сам по себе этого не доказывает.

## 4. Проверка пользовательского сценария и полный Eval

На сайте нажмите **«Открыть тестовый портфель»**. После успешного короткого прогона:

1. «Построй динамику DPD 90+ за весь доступный период. Укажи первую и последнюю даты и изменение в процентных пунктах». Проверьте график, таблицу, даты и источник MCP.
2. В том же диалоге: «А теперь только потребительские кредиты в Приволжском регионе». Проверьте наследование периода и новый MCP-вызов.
3. «А теперь автокредиты в Сибирском регионе за тот же период». Проверьте смену области без переноса старых чисел.

Полный Eval: повторите команду выше **без `--limit 1`**, с `--max-llm-requests 40` и `--output reports/acceptance-yandex-live.json`. Это 17 вопросов, включая новые формулировки, стресс и цепочку памяти. Сохраните фактические результаты, даже если часть проверок не пройдена. Для повторяемости нужен второй независимый прогон той же конфигурации; первый успешный вопрос не заменяет весь Eval.

## 5. Если первый запрос не прошёл

| Ошибка | Что проверить |
|---|---|
| `401` | Введён секрет API-ключа, ключ действует, `LLM_AUTH_SCHEME=api-key` |
| `403` | Роли сервисного аккаунта, scope ключа, права на каталог и доступ к модели |
| `400` | Формат URI модели, совпадение каталога, выбран именно `responses` |
| `404` | Base URL заканчивается на `/v1`; путь `/responses` добавляет приложение |
| `429` | Квота/ограничение Яндекса; дождаться разрешённого времени, не запускать большой Eval |
| Исчерпан лимит выходных токенов | Модель не завершила план; в журнале будет контролируемая ошибка, частичный вызов не исполняется |
| Модель не выбрала нужный инструмент | Подключение могло сработать, но план не прошёл проверку; сохранить JSON-отчёт для разбора |

Сервер показывает безопасный статус ошибки без тела ответа провайдера, ключа и приватных заголовков. Приложение не переключается в DEMO, на другую модель или платный тариф автоматически.
