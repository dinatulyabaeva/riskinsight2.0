# Архитектура RiskInsight 2.1

## Поток одного анализа

1. Web отправляет вопрос, выбранные набор, дату и фильтры, а также необязательные идентификаторы диалога и запроса. `APP_ACCESS_TOKEN` защищает доступ.
2. FastAPI проверяет набор, лимиты и серверную память. Изменение области в интерфейсе сбрасывает диалог; повтор успешного запроса с тем же идентификатором возвращает прежний результат.
3. `MCPClient` запускает отдельный Python-процесс, выполняет `initialize`, `notifications/initialized` и `tools/list`. `EvidenceSession` запрашивает `get_dataset_context`.
4. LLM получает вопрос, схемы, доступные даты и категории, фактическую область предыдущего анализа. Модель выбирает аналитические `tool_calls`.
5. Оркестратор проверяет схемы, набор, даты, явные фильтры и интервал. Неизвестные поля и произвольные пути не разрешены. Обнаруженная подмена смысла анализа отклоняется; исправление выбора делает модель.
6. Успешные MCP-вызовы `tools/call` выполняют параметризованный SQL только для чтения. Журнал `trace` хранит фактические аргументы и структурированные результаты.
7. Модуль `evidence.py` формирует числа, текст и спецификации графиков из текущего `trace`. Вычисления не передаются языковой модели. У каждого графика есть `source_ref`, даты, фильтры и единицы.
8. Web показывает отчёт, график, таблицу, источники и кнопки экспорта. Сервер сохраняет до 6 успешных обменов и фактическую область для следующего вопроса.

Успешное планирование обычно требует одного вызова модели. До 3 попыток нужны для исправления выбора или параметров; число ограничено настройкой. Модель не может исполнять произвольные сетевые запросы, SQL, команды оболочки или код. DEMO — отдельный явно обозначенный сценарный режим без модели, но с настоящим MCP.

## Модули

| Модуль | Ответственность |
|---|---|
| `main.py` | API, авторизация, лимиты, импорт и пример, хранилище диалогов |
| `conversations.py` | Срок хранения, ограниченная история, сброс области, идемпотентность |
| `agent.py` | Запросы и ошибки, адаптеры совместимого с OpenAI API и Ollama, DEMO, публичный `run_agent` |
| `orchestration.py` | Планирование модели, валидация области и полноты анализа, выполнение MCP |
| `evidence.py` | Форматирование фактов и спецификаций графиков с ограниченным набором полей |
| `mcp_client.py` / `mcp_server.py` | Инициализация JSON-RPC, инструменты и ресурсы, отдельный процесс |
| `analytics.py` / `tool_registry.py` | Формулы, фиксированный SQL, Pydantic-контракты |
| `datasets.py` / `xlsx_import.py` | Каталог версий и атомарный импорт |
| `static/evidence-charts.js` | SVG и таблицы по проверенной спецификации, без HTML от модели |

## Границы доверия

История и строки данных не являются инструкциями. Область/числа старых ответов не заменяют текущие MCP-источники. Набор закреплён клиентом и повторно проверяется сервером. API не читает портфельные таблицы напрямую. Переменные окружения с ключами не передаются MCP-процессу.

Названия и ответы выводятся текстовыми DOM-узлами; непроверенные URL и код не исполняются. SVG строится программно только для допустимых типов графиков, конечных чисел и источников текущего `trace`. `null` остаётся пропуском. Остатки разных дат не суммируются.

## Стабилизация и пределы хранения

Встроенный генератор использует seed = 42, `teaching-v1` — фиксированные правила. XLSX хранится в репозитории; импорт сохраняет отдельную неизменяемую базу SQLite и SHA-256 исходных байтов. Структура таблиц (`builtin`/`xlsx`) отделена от признака `synthetic`. Контрольный хэш логических ячеек и эталоны на основе `Decimal` позволяют независимо воспроизвести числа.

Объём памяти диалогов и кэша в оперативной памяти ограничен; рестарт очищает их. На Render Free также могут исчезнуть загруженные базы SQLite. Это явно показывается пользователю. Поставляемый пример воспроизводится повторным импортом; устойчивость чисел не означает гарантии долгосрочного хранения файлов.

## Что измеряется отдельно

Интеграционные тесты pytest и контрольный прогон (`controlled acceptance`) заменяют внешний ответ LLM заданным тестовым ответом. MCP-процессы, импорт, SQL, память и формирование графиков в этих проверках настоящие. Eval живой модели нужен, чтобы проверить её выбор инструментов. Для публичной версии отдельно проверяются коммит сборки и пользовательский сценарий извне.
