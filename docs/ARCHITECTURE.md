# Архитектура и границы доверия

## Компоненты

`app/main.py` обслуживает Web UI и JSON API. Bootstrap создаёт только встроенную синтетическую БД. XLSX endpoint валидирует файл и регистрирует отдельную неизменяемую SQLite-базу. Портфельные чтения идут через MCP; список наборов и журнал импорта — служебные данные registry. На каждый запрос дашборда или агента открывается отдельная MCP-сессия с новым child process; все вызовы одного анализа используют одну сессию. Concurrency ограничен semaphore, по умолчанию 2. Это простой жизненный цикл для MVP, но имеет накладные расходы запуска процесса.

`app/mcp_client.py` выполняет initialize, проверяет версию/capabilities, отправляет notifications/initialized и последующие запросы с id. Запросы сериализуются lock. При закрытии завершается stdin; далее wait/terminate/kill с тайм-аутами. Секреты LLM и токен Web API не наследуются дочерним процессом. stdout читается только как JSON-RPC.

`app/mcp_server.py` — небольшая реализация MCP revision 2025-06-18. Tools и resources — поддерживаемый поднабор. Валидация аргументов через `tool_registry.py`; вызовы направляются в `Analytics`. Неизвестный tool возвращает protocol error, ошибки пользовательских аргументов — tool execution result с isError=true. Нет remote HTTP, публичного MCP-порта, произвольных файлов, SQL или команд.

`app/analytics.py` открывает SQLite URI `mode=ro` и устанавливает `query_only`. Группировки выбираются из allowlist. Values передаются bound parameters. Для сумм используются копейки. Структурированные результаты компактны и содержат provenance, filters, dates, unit conventions.

`app/agent.py` получает schemas через tools/list и передает их модели. Tool-call arguments JSON разбираются, неизвестные tools не вызываются. Каждый реально выполненный вызов добавляет [Tn], аргументы, результат, success/error и длительность. Неудачные tool calls тоже остаются в журнале.

`static/app.js` отображает дашборд и ответ безопасными текстовыми DOM-узлами. Источники [Tn] открывают соответствующий фактический trace. Экспорт формируется локально в браузере без отправки данных третьим лицам. Ключ LLM никогда не попадает в браузер.

## Два режима

В LLM-моде основная логика выбора аналитических действий и интерпретации находится в модели. Python считает числа, а не пытается предсказывать намерения по ключевым словам.

В DEMO действия задаются явным enum сценария. Пользовательский свободный вопрос не интерпретируется. Отчеты шаблонные, но MCP, SQLite и метрики настоящие. Нельзя считать DEMO доказательством успешной интеграции внешней модели.

## Доверие и ограничения

Область анализа из UI является default, а не security boundary: это общий набор экземпляра приложения. dataset_id закреплён на запрос и не может быть изменён моделью. Внутри набора модель может выбрать другую дату/фильтр при явном запросе пользователя и должна описать ее. Требований per-user row-level security нет и их реализация не заявляется.

История чата только визуальная: предыдущие ответы не передаются модели. Это исключает неявное переиспользование устаревших source refs и упрощает аудит одного запроса. Цена — отсутствие полноценного многотурового разговора; вопрос должен быть самодостаточным.

MCP stdio выбран для приватного внутриконтейнерного взаимодействия. Для удаленного сервера потребуются официальный HTTP-транспорт, аутентификация, Origin checks и отдельные интеграционные тесты. Называть `/api/chat` MCP endpoint нельзя.

## Поведение при сбоях

Нет доступного среза -> ошибка, не подмена последним. Пустая допустимая выборка -> нулевой остаток и null доли. Неверная LLM-конфигурация -> 503; upstream API/формат -> 502; общий тайм-аут -> 504; исчерпанная квота -> 429. При протокольном сбое MCP -> 503. Необработанные ошибки инфраструктуры требуют проверки серверного лога; пользователь не получает секретов или stack trace через штатные сообщения.

MCP stderr не передается в UI; встроенный клиент его отбрасывает, чтобы не блокироваться на pipe. Для диагностики запустите сервер отдельно с SDK/Inspector и просмотром stderr. Это ограничение наблюдаемости MVP.

## Импорт и выбор набора

```text
UI file bytes → FastAPI (auth, streaming <=10 МБ, semaphore)
                  → worker thread: xlsx_import
                    ZIP/XML preflight → openpyxl(read_only, data_only=False, keep_links=False)
                    validation → temporary SQLite → close handles → atomic rename
                    → DatasetStore transaction: dataset + import report
UI dataset_id → API → bound MCPClient → EvidenceSession → stdio tools/call(dataset_id)
                    → Pydantic → DatasetStore.resolve(ID) → Analytics(mode=ro)
                    → aggregates + calculation + dataset_id → dashboard / LLM / trace
```

`app/datasets.py` хранит registry и журнал в imports/catalog.sqlite рядом с DATABASE_PATH. ID удовлетворяет allowlist builtin|upload_<UUID>; неизвестные, файловые и URL-значения отклоняются. Registry не хранит произвольный путь; имя файла базы выводится исключительно из серверного ID. Исходное имя XLSX — только отображаемая подпись, текст никогда не исполняется. Symlink файла импорта не разрешён.

`app/xlsx_import.py` — дополнительный write-path, авторизованный задачей импорта; MCP и агент не получают инструментов записи. Ошибки отдельных строк не приводят к частичной загрузке. Файл БД целиком создаётся и закрывается до rename, затем одной транзакцией фиксируются registry и журнал. При ошибке регистрации файл удаляется. При аварии процесса между rename и registry возможен неиспользуемый файл; он не виден в списке и не разрешается MCP. Ручная очистка таких файлов не должна удалять зарегистрированные наборы.

Встроенная схема остаётся прежней. Загруженная схема xlsx-v1 хранит product/region/risk_band в snapshots, поэтому признаки одного кредита могут меняться между датами. loans хранит уникальные loan_id; деньги — INTEGER копейки, отсутствующие значения — SQL NULL. Analytics выбирает одну из двух фиксированных SQL-основ по серверной metadata. Названия таблиц/колонок не поступают от пользователя.

Вкладка хранит выбранный ID; глобального «активного набора» на сервере нет, разные вкладки не влияют друг на друга. При смене набора сбрасываются фильтры, прежний ответ и KPI; устаревшие HTTP-ответы отбрасываются по счётчику запроса. Во время анализа смена набора заблокирована. Реальные arguments.dataset_id сохраняются в источниках и экспорте. Отсутствие PD/LGD не превращается в нулевые потери.

## Windows и эксплуатация

Требуются Python 3.11+ и один Uvicorn worker без --reload. MCP использует sys.executable и asyncio.create_subprocess_exec без shell; read-only SQLite URI строится через Path.as_uri. При записи SQLite явно закрывается (обычный with connection сам по себе этого не делает), затем выполняется os.replace. Новые компоненты не требуют Excel, COM, bash или LibreOffice. CI включает Windows/Linux и браузерный сценарий. Compose хранит каталог данных в именованном томе; для Render необходимо отдельно настроить постоянный диск.
