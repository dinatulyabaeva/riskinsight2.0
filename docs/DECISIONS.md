# Архитектурные решения (ADR)

## ADR-001 — FastAPI + небольшой статический UI

Решение: отделить API от интерфейса, не требовать Node-сборки. Причина: явная демонстрация сквозного сценария, тестируемость и единый Docker-контейнер. Цена: ручная реализация DOM/графиков вместо готовых компонентов Streamlit.

## ADR-002 — Python/SQL считает, LLM выбирает и объясняет

Решение: метрики и декомпозиция детерминированы; модель получает агрегированные результаты tools. Причина: воспроизводимость чисел. Цена: все разрешенные виды анализа нужно реализовать заранее; свободный SQL и произвольный код запрещены.

## ADR-003 — Настоящий MCP stdio, небольшой wire implementation

Решение: tools/resources subset protocol 2025-06-18, отдельный процесс, настоящий handshake и вызовы. Причина: самодостаточная проверка в среде без возможности установить SDK и простая локальная инфраструктура. Цена: часть протокола поддерживается явно, не весь MCP. Требуются независимый sdk_smoke/Inspector и дальнейшая поддержка совместимости. Для remote deployment предпочтительнее отдельная миграция на официальный SDK, а не расширение самописного HTTP-транспорта.

## ADR-004 — Неизменяемая синтетическая панель (расширено ADR-008)

Исходное решение: фиксированный seed, без пользовательской загрузки файлов. Расширено ADR-008: встроенный набор сохраняется, добавлен отдельный импорт. Причина: воспроизводимость и отсутствие реальных клиентских данных. Цена: упрощенный процесс кредитования, не валидированный risk model и нет multi-user data isolation.

## ADR-005 — DEMO не называется AI

Решение: отдельные сценарии и явная метка режима. Причина: приложение можно проверить без API key, не вводя проверяющего в заблуждение. Цена: для выполнения LLM-критерия ключ и live smoke обязательны.

## ADR-006 — Источники вместо скрытых рассуждений

Решение: показывать инструмент, параметры, результат и source_ref, а не chain of thought. Причина: проверка фактов и воспроизводимость действий. Цена: ссылка на существующий tool не доказывает, что все выводы модели корректны; нужен human review.

## ADR-007 — Упрощенная публикация, но без вымышленных статусов

Решение: Docker, Compose, Blueprint и инструкции; не писать URL до реального деплоя. Причина: внешние аккаунты и секреты принадлежат пользователю, платные ресурсы не создаются без его подключения/подтверждения.

## ADR-008 — Реестр версий XLSX и read-only MCP

Решение: отдельная SQLite-база на каждый корректный импорт, случайный dataset_id и служебный registry. Требование XLSX явно расширяет прежний единственный bootstrap write-path из AGENTS.md. Портфельные чтения остаются только через MCP; importer не добавлен в каталог инструментов. Причина: сохранить воспроизводимость DEMO и исключить подмену произвольного пути. Цена: общий доступ без tenant isolation, хранение нескольких копий данных и необходимость постоянного диска.

Выбор фиксируется на запрос в MCPClient; модель не может переключить набор. Пропуски PD/LGD приводят к null EL и отказу stress; неполный EL не выдаётся за общий. Формулы и активное содержимое отклоняются. Для Windows соединения SQLite явно закрываются до переименования.


## ADR-009 — Отдельное планирование и представление проверенных результатов

В версии 2.1 удалены ранние ветки, выполнявшие анализ без модели под меткой `llm`. Модель выбирает аналитические `tool_calls`; числовой текст и графики строит `evidence.py` из текущего MCP-журнала. Для выбора доступны до 3 попыток, обычный успех требует одного обращения. Это снижает риск выдуманных чисел и число лишних обращений к бесплатному провайдеру. Цена — программно определённые виды представления вместо свободного эссе. Роль каждого компонента явно отражена в `provenance`. Это уточняет прежнее разделение ролей из ADR-002: числовой отчёт в текущей версии формирует программа.

## ADR-010 — Рабочая память, но новые источники для каждого вопроса

Сервер хранит до 6 успешных обменов и последнюю область анализа, TTL — 1 час, не более 64 диалогов. Явное уточнение меняет фильтр или период; изменение области интерфейса, смена набора и сброс анализа очищают контекст. Старые числа не используются как доказательства. Идемпотентный `client_request_id` защищает от повторной работы после потери HTTP-ответа. Один процесс и ограниченная память соответствуют учебному бесплатному хостингу; после рестарта пользователю сообщается о начале нового диалога.

## ADR-011 — Многосценарный учебный файл и независимый oracle

Поставляются фиксированный XLSX с 1 200 кредитами на 12 датах, генератор и эталоны на основе `Decimal`. Эталоны независимы от SQL и `Analytics`. Исходные данные не меняются от вопроса. SHA-256 файла в каталоге и MCP показывает версию; логический хэш ячеек не зависит от ZIP-метаданных XLSX. Схема хранения XLSX отделена от признака происхождения `synthetic`.

## ADR-012 — Честные уровни проверки

Провайдер с заданными тестовыми ответами подходит для проверки интеграции, но не качества понимания текста. Eval живой модели имеет отдельный явный режим, сохраняет все ошибки и параметры фактической модели. Исторические оценки прежних моделей не переносятся на версию 2.1. Публичный сервис через HTTPS проверяется отдельно от тестов кода и SDK.

## ADR-013 — Бесплатный хостинг и восстановимый пример

Поставляемый пример хранится в Git и импортируется одной кнопкой; при утрате локального диска его можно восстановить. Пользовательские загрузки и диалоги на Render Free не объявляются постоянными. Платный диск и смена плана не включаются автоматически. Ошибка квоты LLM остаётся видимой, автоматической замены на платную модель нет.

## ADR-014 — Responses API и явно выбранный платный провайдер

В версии 2.2 добавлен отдельный Responses-адаптер для Yandex AI Studio и совместимых API. Владелец явно выбрал возможность использования платного Yandex API после ограничений бесплатного провайдера. Формат функций, идентификаторы `call_id`, завершение ответа и учёт токенов преобразуются в существующий контракт планировщика. Путь MCP, валидатор области, расчёты и представление результатов едины для всех провайдеров. Выбор провайдера в приложении и локальном Eval использует одну фабрику.

`store:false` не создаёт удалённую память Responses; ограниченная память RiskInsight сохраняется. Служебные элементы ответа при продолжении вызовов передаются обратно провайдеру, но не публикуются как текст анализа. Ошибки аутентификации, квоты и неполные ответы видимы и не инициируют незаметный повтор, DEMO или замену провайдера. Цена решения — отдельные адаптерные тесты и необходимость нового живого Eval конкретной модели. Наличие ключа и успешные тесты с заданным HTTP-транспортом не объявляются результатами живой модели.
