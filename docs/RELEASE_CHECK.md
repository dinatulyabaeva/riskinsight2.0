## Что не считается закрытым проверками версии 2.1

1. **Eval реальной Ling на новой версии.** Секреты пользователя отсутствуют в этой среде; контрольный прогон не заменяет реальную модель. Нужен сохранённый отчёт с ответами, ошибками и точной конфигурацией.
2. **Публичная сборка 2.1.** Нужно сверить `build_commit`, пройти вход и полный сценарий извне. Существования прежней ссылки недостаточно.
3. **Согласование и оценка преподавателя.** Они не выводятся из результатов pytest или числового эталона.

Финальный Eval живой модели можно запустить локально с настроенной моделью либо через опубликованный сервис. Для второго способа используются `--provider live`, `--base-url https://riskinsight.onrender.com` и `--expected-commit` с полным SHA опубликованного коммита. Локально нужен только `APP_ACCESS_TOKEN` сервиса; ключ LLM остаётся на Render. Точные команды приведены в [README](../README.md#eval-живой-модели-через-опубликованный-сервис). При исчерпании квоты или лимита провайдера отчёт должен сохранить ошибку, а не объявить успех.

## Разделение доказательств

Тесты формул и SQL проверяют реализованный расчёт. Контрольный прогон проверяет интеграцию при заданном плане. Eval живой модели показывает, сможет ли она выбрать план по новой формулировке. Браузерные проверки и проверка опубликованной сборки подтверждают пользовательский сценарий. Ни один из этих пунктов сам по себе не достаточен для заявления «проект полностью готов».
